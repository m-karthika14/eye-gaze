# /experiments

Runnable, reproducible scripts for the five systems compared in this research (see `MASTER_PROJECT_DOCUMENT.md` Section 10):

| System | What It Does |
|---|---|
| S0 | Gaze → nearest key → text (baseline, no language, no adaptation) |
| S1 | Hard-selected key → post-hoc language correction |
| S2 | S1 + adaptive / confidence-aware keyboard |
| S3 | S2 + online user adaptation |
| S4 | S3 + joint gaze-probability + language decoding (core method) |

- **Phase 2 (done):** `s0.py` — `S0System` composes `decoder.nearest_key` + `decoder.dwell` + `decoder.text_buffer` into the S0 baseline. Used live by `/backend` (one sample at a time via `process_sample`) and, later, by Phase 9 for batch replay of recorded/simulated gaze sequences via `run_sequence`. `test_s0_synthetic.py` is a regression check against a fabricated gaze path (no webcam needed): `.venv/Scripts/python.exe -m experiments.test_s0_synthetic`.
- **Phase 3 (done):** `calibrate_uncertainty.py` — shows a sequence of known target keys, records predicted `(mu, sigma)` and raw gaze angle against ground truth, then (1) re-derives `config/gaze_mapping.yaml`'s `half_fov_*_rad` directly from real gaze angles via `analyze_range()`, and (2) computes/writes a robust (median-based, outlier-resistant) `sigma_scale` correction to `config/decoder_params.yaml` via `analyze()`. Has been run against real data (two real bugs -- a warm-up-window artifact and a range that got stuck too wide -- were found and fixed along the way; see commit history). Also prints `print_accuracy_dashboard()`: a per-trial table (target vs. predicted key, signed error, hit/miss) plus aggregate key-hit accuracy, mean signed error (reveals directional bias vs. plain noise), and a left/right and top/bottom split (surfaces axis-specific problems like the yaw-inversion bug at a glance). The actual math behind the dashboard and `analyze()` lives in pure, side-effect-free `compute_accuracy_dashboard()`/`compute_sigma_scale()` (the `print_*`/`analyze()` wrappers just format and print their output) -- `backend/calibration.py` imports these directly to drive the in-app calibration flow (see `/backend`'s README), so the terminal script and the product UI can never silently compute different numbers. `test_uncertainty_synthetic.py` is the no-webcam regression check for all of the above.
- **Phase 4 (done):** `test_char_lm.py` — no-webcam regression check for `decoder/char_lm.py` (valid probability distributions, sensible predictions on common prefixes, real text scored above scrambled text). `test_word_suggestions.py` — live check for `llm_services/word_suggestions.py` against the real Groq API: basic completion (`"hel"` → `["help", "hello"]`), cache-hit speed, and fallback-without-API all verified.
- **Phase 5 (done):** `gaze_sequence.py` — the shared `GazeObservation`/sequence format all of S1-S4 run on (one observation per intended character; `simulate_gaze_sequence()` generates synthetic sequences at a controllable noise level until Phase 9 collects real recorded ones). `s1.py`, `s2.py`, `s3.py`, `s4.py` — all four systems, sharing `decoder/beam_search.py`'s noisy-channel search and differing only in what `P(G|T)` they feed it: S1 collapses gaze to a hard-selected key first and uses a generic, position-blind confusion model (language can only guess it might be a typo, not which nearby key was plausible); S2 is decoding-identical to S1 for batch replay (the adaptive keyboard only matters live -- see `s2.py`); S3 adds a bias-correction hook that's a true no-op until Phase 7; S4 uses each observation's REAL Gaussian key-probability distribution (`decoder/key_probability.py`) instead of a hard choice. `test_s1_s4_synthetic.py` verifies all of this mechanically, including H1's predicted pattern: S4's character-accuracy advantage over S1 grows with gaze noise (+0.018 at low noise -> +0.234 -> +0.294 at higher noise, before narrowing at extreme noise) -- a real, working demonstration of the core research mechanism, though the statistically-powered version of this comparison is Phase 9's job, not this mechanical check's.
- **Phase 6 (done):** `test_phase6_synthetic.py` — no-webcam regression check for `backend/adaptive_layout.py` (product layer, lives in `/backend` not here since it's not part of the research decoder): row bounds/no-gaps preserved under resizing, likely keys actually grow, no key vanishes, and suggestion acceptance correctly replaces the in-progress word via `decoder.text_buffer`'s existing primitives.
- **Phase 9:** the four research experiments (H1 main comparison, noise sensitivity, H2 online-adaptation comparison, real-world validation) run and logged here.

**Status:** S0 through Phase 6 done, verified via synthetic tests, live end-to-end runs (including a real dwell selection triggering a real Groq suggestion fetch), real calibration data, live Groq API calls, and (for S1-S4) a working mechanical demonstration of H1's predicted pattern.
